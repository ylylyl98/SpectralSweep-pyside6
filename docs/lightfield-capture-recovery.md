# LightField 采集卡住时的保护与恢复

本轮改进覆盖 `Capture`、数据读取、复制、dataset 释放和采集后的波长读取。
独立的 Python 监控线程只检查缓存与单调时钟，不向 LightField SDK 发查询。
界面仍能响应并不代表采集线程正常；超时记录也不等于设备已经停止。

## 等待预算

默认预算为以下两者的较大值，单位为秒：

```text
30
3 × exposure_ms / 1000 × accumulations × capture_frames + 15
```

例如 300 ms × 10 次累积、Capture 1 帧，SDK 预算为 30 秒。采集前的 SDK 设置读取、
Capture、数据读取、复制、dataset 释放和波长读取共享这份累计预算；阶段切换不会重新计时。
缺少缓存设置时使用 30 秒的等待预算；这不能证明相机硬件有故障。

纯本地的元数据记录（开始、完成及错误记录）使用独立的 120 秒持久化预算，
本地序列化、写盘与历史索引耗时不占用 SDK 的曝光/读取预算。返回后保留 SDK 原有剩余预算，
不会重新给一份完整预算。元数据快照中的硬件 getter 仍受 SDK 预算保护。
元数据持久化超时显示 `LightField metadata persistence stalled`，不能据此判断相机卡死。
本地写入也可能尚未返回；这种情况下同样保留设备所有权，等待返回、完成清理后才可恢复连接。

外部触发或特殊实验可在本机配置 `lf6.lightfield_capture_wait_timeout_s` 为正的有限秒数，
覆盖默认预算。`null` 使用默认计算。设置在下一次建立 LightField 连接时生效；
预算不足会要求恢复连接，应按实验实际最长等待时间设置。此选项不改变曝光时间。

## 超时之后

- 界面显示卡住的阶段、已等待时间及 Dual Gate 已保存的点数。
- 同一连接保持占用，禁止新采集、修改采集设置、切换共享光路及重新连接。
- SDK 调用尚未返回时禁止断开和关闭程序；Stop 只记录停止请求，不宣称取消成功。
- 调用迟到返回后，释放返回的 dataset，丢弃迟到数据，实验记为失败。Stop 不覆盖失败状态。
- Dual Gate 沿用失败时保留 SMU 最后状态的策略，不自动归零、重试或续跑。
  “最后设置值”不代表当前电压读数，恢复实验前需自行核实仪器状态。
- 清理完成后仍要求断开、重新连接 LightField，只有新连接才可再次采集。
  如果 SDK 始终不返回，本批改进无法安全中止它，不能通过重复点 Stop 或重新开始来恢复。

常规成功、普通异常及超时返回的 dataset 都在拥有该对象的线程中释放一次。
NumPy 数据在 .NET 数组解除固定前完成复制；释放失败也会保留恢复锁。
这些修改修正了资源生命周期问题，但尚不能证明它是此前 Capture 卡住的根因。

## 诊断和通知

实际 LightField 连接的每次故障写入本机：

```text
%APPDATA%\SpectralSweep\diagnostics\lightfield-capture-<PID>.jsonl
```

记录包含阶段、预算、线程栈的位置、运行/采集 ID、测量点及输出文件等缓存信息。
`timeout_domain` 区分 `sdk` 与 `metadata`，`elapsed_s` 是整次操作的总时间，
`sdk_elapsed_s` 与 `metadata_elapsed_s` 分别累计两类耗时；`timeout_s` 是触发故障的预算，
`sdk_timeout_s` 与 `metadata_timeout_s` 保留各自预算，`wait_elapsed_s` 是首次超时时该预算已消耗的时间。
这些字段来自本地缓存，不额外查询设备；
不记录线程局部变量。日志写入失败不会解除恢复锁。没有通知订阅也会监控并写本地诊断；
已配置 ntfy 通知时，达到等待预算后通过已有通知队列发送一次故障提醒，
不用等 `Capture` 返回或实验最终结束。提醒包含卡住阶段、已等待时间、恢复要求和诊断路径；
同一次故障的重复轮询不会重复发送。通知沿用本机已有订阅，网络发送不阻塞采集线程。

`capture_completed` 只代表 SDK Capture 阶段完成，不代表该点已经保存。
Dual Gate 已改用文件级记录：固定设置下不生成逐点 capture 事件，
`file_completed` 只在 CSV 成功关闭后写入；停止或失败即时保存当前文件进度。
逐点硬件参数校验、超时保护和数据集释放仍保留。
数据读取、释放或波长校准阶段随后超时的点不会写入测量 CSV，也不会推进已保存点数。
既有 CSV 行保留。实验正常结束、失败或停止时，原有 metadata 最终化流程仍负责登记文件。

本批没有加入 SDK 进程隔离或断点续测。已启动的程序不会自动加载这些核心修改；
应先处理当前测量和仪器状态，再通过根目录 `launch.bat` 启动更新后的程序。
