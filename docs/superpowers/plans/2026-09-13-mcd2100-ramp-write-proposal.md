# 本系统扫速编辑与动态预算：范围提案

用户在已完成只读核查后提出加入改变 sweep rate 功能。此文是新增功能的设计提案，不是实机写入授权；本轮未修改生产代码或操作仪器。

## 可核实的基础

本地 SDK `CRYO2100/magnet.py:538` 提供 `setRampRate(channel,index,range_this,rate)`，发送同顺序 JSON params；返回成功不带设置值，必须另用 `getRampRate(channel,index)` 读回。现有 Current 前四项读回与厂商界面 A/A/s 数值一致；Default 及 Current 第五项仍有错误。固件1.1.5的具体生效/持久性及允许写入状态尚未获证明。

磁体系统220507规格只明确0–40 A最大0.0344 A/s、40–44.0116 A最大0.0172 A/s。第三段及以后超出所给磁体额定电流区间；显示存在不等于可据此开放编辑。现有App磁场范围不随本功能扩大。

## 建议第一版

1. 编辑已核实的前两段普通Current速率；区间边界固定，不编辑Fast、Default或其他段。按用户最新要求，以 **T/min 作为输入和编辑单位**，旁边只读显示对应 **A/s**；当前读回值也以T/min主显示、A/s辅助显示。保留原始index及区间A。输入必须有限正数且不超过各段系统规格上限；最低可用速率/分辨率若SDK无定义，不能编造，设备拒绝须原样报告。
2. 显示当前读回值、拟设置值和来源；明确区分“界面草稿”“写入已提交”“读回确认”“失败/结果未知”。不因编辑spinbox自动发送。
3. 单独“应用扫速”按钮。App空闲、没有测量/准备/磁场动作/其他owner任务时才允许提交；不为取得条件而切换模式、发送Stop或改变磁场。SDK本身允许的仪器状态须用匹配固件资料核实，不能自行把Driven或Persistent设为已证实要求。
4. 复用已有controller连接和owner队列，完整操作为：读取目标段及必要状态→核对边界和版本/会话→串行写入用户修改段→逐项读回核对→更新缓存。全部SDK调用在owner执行，GUI只接收结果。外部程序仍可能修改设备，App互锁不能提供跨程序事务保证。
5. 部分失败停止继续提交剩余写入，尽可能以只读确认已提交段实际状态；不盲目重试、不自动回滚、不关闭温控或磁场。未结束的owner调用仍需自然drain。取消只阻止后续提交，不能宣称撤销已经执行的设置。
6. 动态预算使用本次连接内已确认Current数据，仅要求路径覆盖段有效；Default/无关第五项错误不阻断估算。磁场按已知磁体系数转换为电流，按绝对电流区间分段，跨零分开累计。预算包含命令/查询/确认余量，另设最大上限；开始时固定预算，不逐次自动续期。修改扫速后，必须完成读回才能以新值估算；缺失路径使用明确标注的回退预算。

## T/min 输入与 A/s 换算

只使用本系统220507规格中的磁体系数 `2044.9 G/A = 0.20449 T/A`：

- 显示：`T/min = A/s × 0.20449 × 60 = A/s × 12.2694`。
- 应用：`A/s = 输入的 T/min ÷ 12.2694`；SDK仍接收A/s，不把T/min原值直接传入。
- 例：输入 `0.1 T/min`，对应约 `0.00815036 A/s`。
- 第一段规格上限：`0.42206736 T/min`，对应 `0.0344 A/s`。
- 第二段规格上限：`0.21103368 T/min`，对应 `0.0172 A/s`。

界面编辑的是速率大小，不用正负号表示扫场方向；方向仍由起点/目标决定。显示舍入不得改变实际提交值，校验使用未舍入换算值和原始A/s上限，不把展示精度当设备分辨率。读回后重新换算展示，并保留设备实际A/s；量化与读回容差仍须核实。此次仅更新设计，不实现或调用写入。

## 实现前必须区分的未知项

- Python wrapper签名已知，但固件1.1.5允许写入的状态、是否即刻生效、是否需额外apply/save、是否持久保存、量化/读回容差未确认。
- 厂商界面同时带range与rate，SDK setter同样要求range；不能把range参数误当无关占位值，必须读取并保持原边界。
- 厂商整表Apply是否还调用其他接口未确认，不照猜测补调用。可用用户提供的页面源码/匹配API说明做离线核查；实机测试由用户另行执行。

## 测试与审查验收

模拟覆盖合法两段、边界不变、非法速率无请求、运行中拒绝、串行队列、逐段写入读回、设备拒绝、写后读回失败/不一致、超时drain、部分提交与取消、旧generation不覆盖新缓存。预算覆盖单段/跨段/跨零、部分表覆盖足够、缺失路径回退、更新读回后预算变化。测试验证不会调用模式/磁场动作接口、不新增连接、不放宽磁场范围。

增加T/min↔A/s换算、两段上限及显示舍入边界测试；确保SDK接收A/s、输入负数不改变方向、读回展示以实际设备值为准。

按用户既定偏好由Astra设计/实现及独立审查，可将实现与审查交给不同Astra实例；不使用Luna除非用户重新指定。设计范围确认后先完成代码与模拟验收，再交用户实机核验。资料未知项不能被测试fake当作已确认设备契约。

## 既有 APS100 路径对照（只读核查）

用户要求检查“PSP”如何修改APS100扫速。本次项目和上级代码检索未定位到明确名为PSP的实现；以下结论限定于现有App的APS100/MCD1000路径，不能代表未提供的其他PSP软件。

- `app/devices/aps100_attodry1000_adapter.py:502` 保留 `set_rate_t_per_min(rate,max_abs_field_t=...)`。先用该adapter配置的磁体系数换算A/s，再读取RANGE 0..4，根据路径最大绝对电流选择相关区间，逐段写 `RATE {index} {rate_a_per_s:.7f}`，用 `RATE?` 读回核对。它不修改RANGE边界、不写RATE5，也没有保存旧速率或自动恢复机制。不能称为独立临时速率接口。
- `tests/test_aps100_adapter.py:249` 的模拟测试调用此函数，0.1T/min、最大2T时修改fake第0段。测试使用另一磁体系数0.20328 T/A，不得复制为2100本系统的0.20449 T/A。
- 仓库调用点检索未发现当前生产UI/workflow调用上述setter；`ui/mcd_panel.py:651` 读取已有profile并记录，随后 `move_to_field` 沿用普通段。第1407行附近明确界面只读策略。adapter运动使用 `SWEEP ... SLOW`，即设备按当前电流选择已有普通段。
- 仓库 `05_Manual APS100 magnet power supply.pdf` 第52页确认原生RATE选择0..4为五个普通段、5为Fast，单位A/s。没有从这条命令查到可绕过普通段表的任意临时扫速参数。SDK写入持久性仍不能仅据原生RATE推断。

本轮未执行任何setter、connect或仪器调用，未修改代码。若PSP指其他软件，需要其明确路径/名称后再核对。

## APS100 手册专项核查

直接检查仓库 `05_Manual APS100 magnet power supply.pdf`，全文检索及相关章节阅读，并渲染查看第18、30、54页；页码以下均为PDF实际页码。命令汇总表的内部引用页码存在偏移，不能沿用其页码替代实际页面。

- 第16、30页：五个连续电流区间，每段自己的速率，外加独立Fast项。不是五套完整预设。
- 第51–52页：`RANGE` 设置边界，`RATE <Range> <Sweep Rate>` 修改选定段速率（A/s）；原生0..4为普通五段，5为Fast。
- 第54页：`SWEEP <Sweep Mode> [fast or slow]` 只有模式选择，没有任意数值扫速参数。普通扫场按电流使用RANGE/RATE；FAST改用Fast速率，退出Fast须指定SLOW。
- 第18、30页：Fast要求Persistent Heater Present=Yes且持久开关加热器OFF；第17页实例是持久模式时的引线电流归零/匹配。它不是正常Driven MCD的第二个可任意使用的扫速预设，也不意味着SDK index5的映射已证实。
- 第27页：前面板菜单编辑须退出并选择SAVE才生效；ESC/DISCARD放弃菜单编辑。第39页：user data存放在非易失存储器。不能据此断言不按面板SAVE的远程RATE只是临时修改；手册未明确远程每个RATE的持久化时机，也未解释attoDRY固件setRampRate的保存机制。
- 第44–60页命令章节及全文未找到任意临时普通扫速override、普通扫速预设库切换、`*SAV/*RCL`保存召回接口或PSP条目。结论限定为此版手册公开接口，不断言其他固件绝无扩展。

据此，保持原分段表完全不变且任意指定普通测量扫速，不能通过此版APS100已文档化接口实现。App可保存原表备份和多套应用侧配置，但切换任意普通扫速仍需改设备当前表，并明确处理恢复。这与把后部index当备用预设不同。只读动态预算不需要任何此类写入。
