# Qt Quick 全页迁移与响应速度检查（2026-10-26）

本轮补齐 Dual Gate 顶部样品/点位/温度输入与 Spectrum 图底部 Fit live、Fit visible、Auto Y 控件。PL/Ref 模式以一个紧凑下拉框呈现，保留原排他选择逻辑，顶部参数保持两行。隔离窗口逐一打开九个主要工作区，检查可见原生输入框、按钮和 item view 的残留；标准文件、颜色和消息对话框继续使用 Qt 原生行为。

Quick 已负责主要工作区的可见业务界面。窗口宿主、部分分组/分隔容器、隐藏状态控件和既有设备控制器/worker 仍保留；这不是删除 Widgets 兼容层或将所有设备服务重写后的纯 QML 应用。

## 定位到的问题与修复

- 访问全部页面后创建了 106 个 QML 引擎，表单重复加载相同组件。现在所有嵌入视图共享由 QApplication 持有的引擎。模型通过各自的初始属性传入，历史窗口不使用引擎全局 context property。关闭一个视图不销毁其他视图的引擎。
- 启动末尾重新应用相同 QSS，导致整个窗口重新 polish 和布局。样式加载器保留重载通知和文件监视，仅在样式和调色板都未变化时跳过重设；切换主题必须重新解析 QSS 中的 palette 颜色。Quick 字体与调色板在页面构建前设置。
- 表格无变化时仍发送整表通知，QML 因而重新读取所有可见单元格。现在按单元格发送差异通知，缓存列信息与下拉选项，并只保留渲染行的检查范围。源控件信号合并处理；没有信号或被屏蔽的旧式更新仍有兜底检查。
- 标量字段改为按源信号标记并合并刷新相关字段。命令栏显示可用性读取已发布的验证状态；实际 Apply/Run 仍重新读取并提交当前编辑，不使用显示缓存作为运行许可。
- Dual Gate 批量填充 loop 表时触发了中间行编辑和重复计划验证。批量填充屏蔽表级编辑通知并恢复原状态；元数据输入立即进入源控件，衍生的文件名/就绪提示合并更新，Run 入口同步验证。
- 相同不可变曲线和相同视口范围曾触发扫描与重绘。现在跳过无变化的曲线/样式/范围更新；可变输入仍建立独立数据快照，connect 掩码也不借用调用者的可变列表。二维图避免重复 fit，手动范围意图仍保留。
- 仅显示校准页就导入物理拟合优化器。现在在实际请求拟合时导入，数值计算与校验过程不变。

共享引擎后另验证了两类生命周期问题：已销毁的图表不被长寿命引擎的告警回调保留；首次打开隐藏图表、完整序列或恢复旧序列浏览状态不会覆盖当前应用主题。

人工截图检查还发现 Spectrum 命令栏的 QWidget/QML 根高度已为 80px，但内部渲染窗口仍为 48px，第二行 Stop 被裁切。现在同步真实渲染窗口尺寸，布局门禁也检查该尺寸；回归以实际 framebuffer 和按钮交互验证，不能只看逻辑坐标。

## 测量方法

使用 Python 3.13.9 / PySide6 6.11.0、Windows 原生隐藏窗口。工具构建九个真实页面类，禁止导入设备/通知运行时，配置、历史和 QSettings 使用临时目录。基线为修改前一个独立进程，优化后使用三个独立进程的中位数；cProfile 使用额外进程，不混入响应时间统计。

冷启动截止点是第一次同步截图，包含导入和页面构建，不是屏幕真正呈现首帧的时间。首次切页包括懒加载表单和同步截图；Dual Gate 在启动时已创建。输入始终使用同一个 `laser_edit` 字段，连续输入相同的 21 个字符，记录最后一个字符到达源控件的时间。空闲 CPU 为单核等效占用，不能与任务管理器整机百分比直接比较。

复测命令与完整指标定义见 [性能工具说明](quick-performance-probe.md)。原始报告保留在本机 `tmp/quick-performance/`。

## 结果

下表前后均使用 software Quick 后端和相同九页隔离数据；“优化前”为一次基线，“优化后”为三个独立进程中位数。操作系统文件缓存没有清空。

| 指标 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 进程入口至首次同步截图 | 10,443 ms | 5,041 ms |
| 九页窗口构建 | 9,057 ms | 3,967 ms |
| 启动阶段同步 QML 加载合计 | 1,813 ms | 456 ms |
| 首次切换未访问页面（各页范围） | 321–807 ms | 107–347 ms |
| 已访问页面切换（各页范围） | 11–28 ms | 10–24 ms |
| 同一字段输入 21 字符到达源控件 | 84.4 ms | 11.4 ms |
| 访问所有页面后的 QML 引擎数 | 106 | 1 |
| 进程工作集，十进制 MB | 769 | 485 |
| Spectrum 空闲，单核等效 CPU | 2.81% | 1.25% |
| Mega Sweep 空闲，单核等效 CPU | 5.01% | 1.88% |

首窗时间减少约 52%，测试输入耗时减少约 86%。优化后两页空闲心跳 P95 约 16.4 ms，没有大于 50 ms 的间隔。暖切页本来就较快，主要改善来自冷启动、首次打开页面与输入引起的同步工作。首次切页仍可能耗时几百毫秒。

另用 Windows 默认后端单独验证，实际渲染 API 为 **Direct3D11**：60/60 帧、每帧 512 点的预计算模拟谱以约 30.2 fps 进入真实 Spectrum 绘图路径，末帧原始数据和曲线数组精确一致。更新回调 P95 1.10 ms；该阶段心跳 P95 23.4 ms、最大 24.4 ms，没有大于 50 ms 的停顿。此项没有调用真实采集、驱动或磁盘写入，不是实际硬件吞吐量。

默认后端这次首窗约 5.45 秒、工作集约 601 MB；它与 software 的资源成本不同，不能将其数值直接用于上述前后比较。三个可比进程和独立 Direct3D11 进程使用相同源码指纹 `abf7bc43c7f9fcb7de57249ad8fa811527bc9ed472101052213419cfa807841e`，均无 Qt/QML 警告、Python 回调异常或硬件导入。前一版独立 cProfile 诊断位于 `tmp/quick-performance/revision-c2f172ef3a/`，不冒充当前源码的计时结果。

## 最终验证

- 全部 `test_quick_*.py` 加样式、物理/常规校准、既有 UI 性能回归：**187 passed，116.54s**。
- 实际 Quick 绘图工厂下的科学回归：**159 passed，26.85s**。与上述套件存在部分覆盖，不将两者相加作为独立测试数。
- Windows 原生隐藏窗口在 100% / 150% / 200% 缩放、两种尺寸、深浅主题下共 **120 张截图**，九页和仪器视图均检查。所有横向范围为零，控件边界和内部渲染窗口尺寸一致，没有 Qt/QML 警告或回调异常。另目视确认深色背景、完整 Stop、模式选择及顶部两行布局。报告：`tmp/workspace-audit/render-fixed-{100,150,200}/report.json`。
- 仓库外源码副本验证通过，包含 **175 项资源**，Spectrum 和九页工作区均从副本加载且配置隔离。报告：`tmp/quick-bundle-responsive-final/report.json`。
- 正式配置文件大小/修改时间和开工前一致；五个已有元数据修改文件的 SHA-256 均未改变。

## 限制

隔离 UI 与模拟连续谱检查不代表厂商驱动连接、真实采集、磁体停止或长时间运行验证。新的大型计划首次建立索引、可变曲线快照、二维图着色与精确非单调路径仍有随数据规模增长的开销。未构建独立 EXE；源码副本验证使用当前 Python/PySide6 环境。

Qt 明确要求外部提供给 QQuickWidget 的引擎存活得比视图更久，本实现将其归属于 QApplication；QQuickWidget 仍存在额外渲染 pass 和主线程渲染限制。[Qt 官方说明](https://doc.qt.io/qt-6/qquickwidget.html)
